# 调货个案：从讯息进来，到远端出货

这份文件回答两件事：

1. 怎么把「顾客怎样回覆」喂给 AI，而且涵盖所有情况
2. 顾客给的 Name / Location / Machine ID / Item no / 收据，怎么变成一份摘要，
   再走到后台核实、最后转真人远端出货

---

## 一、整条流程

```
顾客来讯
   |
   v
[1] 讯息收进 messages 表          src/whatsapp.js  ingestMessage()
   |
   +--> [2] 自动读出个案资料       src/intake.js    extractIntake()
   |        只填空的栏位，留一条 note
   |
   v
[3] 分诊：这属于哪一种情况         src/triage.js    triage()
   |     确定性的关键字 + 个案状态，不是模型判断
   |
   +-- 该转真人 --> 停在这里，不呼叫 AI
   |
   v
[4] 产草稿                        src/ai.js        draftReply()
   |     剧本 + 个案摘要 -> Claude -> 一段草稿
   |     只产草稿，永远不送
   v
[5] 人看过、改过，才发出去
```

后面的核实与出货：

```
资料齐 + 收据齐
   |
   v
[6] 阶段改「核实中」，人去查两个系统
       机器系统   delivered / pending / faulty
       FINEXUS    captured / void / reverse / refunded
   |
   v
[7] 两个状态一填回来，下一步是算出来的   src/casefile.js  verifyDecision()
```

| FINEXUS | 机器系统 | 结论 | 阶段 |
| --- | --- | --- | --- |
| captured | pending / faulty | 钱收了、货没出 → 远端出货 | 待远端出货 |
| captured | pending / faulty，但顾客不在现场 | 等他下次来 | 等待下次到访 |
| captured | delivered | 两边都说成功 → **不要再出一次**，交给人 | 已升级真人 |
| void / reverse | 任何 | 钱没真的扣走 → 请顾客查银行自动退款 | 退款检查 |
| refunded | 任何 | 已退款 → 请顾客查帐户 | 退款检查 |
| 任一边是 unknown | | 还没查完，不下结论 | 核实中 |

远端出货**永远由人按**。程式只负责算出「现在可以出了」，不会自己出。

## 二、资料摘要是怎么长出来的

### 顾客填的表格

顾客收到的是固定四项：

```
Name :
Location :
ID Machine ( Shown on the screen left side) :
Item no :
```

`extractIntake()` 只做确定性解析：**有标签才取值，没标签就当作没提供**。

- 认得英文 / 马来文 / 中文标签（`Name` / `Nama` / `姓名`…）
- 值可以在冒号后面，也可以在下一行
- WhatsApp 的粗体星号、项目符号、贴上来的零宽字元都会清掉
- 机号大写去空白（`rfh 012` → `RFH012`），金额正规化（`RM 5.50` → `5.50`），
  时间转 24 小时制（`2:30 pm` → `14:30`），日期转 `YYYY-MM-DD`（日在前，马来西亚写法）
- 顾客写 `-` / `n/a` / `不知道` 一律当成没填

**不会做的事**：从一句「我在 KLCC 那台机器 12 号」里猜出机号或品项。
猜错的机号会一路带到 FINEXUS 核实，那时候才发现的代价，比多问顾客一句高太多。

### 写进个案的规则

`ingestMessage()` 收到顾客发来的新讯息之后，会把读到的栏位填进 `customers`：

1. **只填空的栏位**。已经有值的一律不动 —— 那个值可能是同事查证过才填的。
2. **只读顾客发来的（`direction = 'in'`）**。我们自己发出去的表格范本里也有
   `Name :`，不挡的话会把范本的空值当成顾客填的。
3. **每一次填都留一条 note**，作者是 `system:whatsapp`。
   资料是机器填的还是人填的，事后要查得出来。

一个例外：自动建档时 `name` 填的是 WhatsApp 暱称，不是顾客自己写的名字。
这种情况会带一个 `暱称待确认` 标签，顾客第一次在表格里写了名字就盖过去，
同时把标签拿掉 —— 之后就跟其他栏位一样不再被覆盖。

### 摘要长什么样

`caseSummary()` 产出的东西，同时给人看、也喂给 AI：

```
Name：Ali bin Ahmad
Location：Hospital Serdang
ID Machine：RFH012
Item no：23
收据：2025-09-12 14:30 RM 5.50
机器系统：pending
FINEXUS：captured
目前：FINEXUS captured、机器 pending：确认顾客在现场后，由真人远端出货。
```

缺的写「—」，不省略。省掉的那一行就是最容易被当成「已经确认过」的那一行。

## 三、怎么喂 AI

### 剧本在哪里改

后台 →「回覆剧本」（只有 admin 看得到）。

一条剧本有四个栏位：

| 栏位 | 意思 |
| --- | --- |
| 名字 | 人看的 |
| 什么时候用这一条 | 会喂给 AI 判断 |
| 回覆范本 | AI 模仿语气，不照抄 |
| 下一步 | 回完之后个案该往哪走 |
| 转真人 | 勾了就**不会呼叫 AI**，直接交给人 |

预设有 33 条，涵盖六类情况：

1. **进线与收资料** — 只打招呼、付了钱没出货、表格填一半、只传收据、
   收据看不清、传错图、找不到机号、只传语音、资料齐了
2. **核实阶段** — 顾客来催、该出货且人在现场、人已离开、回来了、
   两边都成功、没扣款、已退款、说退款没收到
3. **出货之后** — 跟进有没有拿到、说没拿到、确认收到结案
4. **要转真人** — 要退款、不会再来、品质过期、出错商品、重复扣款、情绪投诉
5. **不该答的** — 价格 / 库存 / 成分 / 健康声明
6. **时间与跟进节奏** — 非工作时间、顾客没回、长期无回应、重复来讯

改完按「保存」，下一次产草稿就会用新的。存在 `settings` 的
`playbook.scenarios`，改坏了删掉那一列就回到预设。

之后程式里新增的预设情境，会在这一页顶端提示「这次多了几条」，
看过按保存就留下来；你改过的同 id 条目不会被盖掉。

### 哪些事不交给 AI 决定

**要不要转真人，是规则决定的，不是模型决定的。**

`src/triage.js` 里的关键字表排在所有判断的最前面。命中「退款 / 品质 /
情绪投诉 / 不会再来 / 重复扣款 / 出错商品」任何一条，就直接停下来，
连问都不问模型。

理由很实际：拦不住的代价，是顾客把一句敷衍的机器人回覆截图出去。
关键字宁可宽一点 —— 误判成「要转真人」只是多一个人看一眼，两边代价不对等。

模型负责的是「把话讲得像人」，不是「决定要不要回」。

### 试跑

「回覆剧本」页最下面有「试一则讯息」：

- **分诊（不呼叫 AI）** — 只看规则怎么判，快、不花钱。改完剧本先按这个。
- **产草稿** — 会真的呼叫模型，一样只产草稿，不会送出去。

## 四、要设的东西

产草稿需要一个 Worker secret：

```
npx wrangler secret put ANTHROPIC_API_KEY
```

没设就是 `503 ai_not_configured` —— 跟桥接机同一个原则：
**没设定等于不能用，不是「先放行看看」**。分诊不受影响，照常运作。

模型预设是 `claude-sonnet-5`，要换的话在 `wrangler.toml` 的 `[vars]` 加
`AI_MODEL`。

呼叫是在 Worker 里发出去的，不是浏览器。API key 不会跟着 JS 送到
每一台开过后台的电脑上。

---

## 五、目前还没做的

- 收据图片里的日期 / 时间 / 金额还是要人读。文字里有写的话会自动收下。
- 阶段不会自动跳。程式算得出「现在该在哪一段」（`caseStatus()`），
  但改阶段还是人按。
- 草稿不会自动发。产出来之后要人看过、改过，才发出去。
